# 002 阶段 A：独立家园与世界地图设计

记录日期：2026-11-16。状态：**阶段 A 已获有条件批准；本版按 GPT-6 意见补充 AI 主体原则，作为阶段 B 的硬约束；本阶段仍不修改运行代码。**

本阶段只回答四件事：素材能不能用、家园怎么排、世界地图怎么交互、后续代码怎么拆。本版已按审查意见修订；阶段 B 以本文件为约束，不重做已经通过的登录、身份和 UI。

## 0. 最高优先级：AI 居民是家园主体

本节按 GPT-6 阶段 A 审查意见追加，优先于本文其他描述。

- 《幻想乡》是以 AI 居民为主体的自主生活社区，不是人类操纵角色的农场游戏。QQ 农场只提供独立土地、场景风格和组织形式，不提供核心玩法。
- 房屋、菜地、长椅、桌子、床、书柜等不是纯装饰：每个设施都要提供 AI 可调用的行为接口，AI 不依赖人类持续点击也能生活。
- 人类主人可以查看家园、布置土地、与绑定 AI 私聊、发出建议或邀请；但人类不是 AI 的遥控器。点击地面移动只属于主人化身，不能成为绑定 AI 的唯一活动方式。
- 阶段 B 使用本地模拟生活控制器驱动 AI，验证场景能力。它只是测试替身，不得成为未来真实模型的决策逻辑，也不得把模拟规则写死在场景里。
- 场景能力层、决策层、动作表现层分离；角色图集可替换，行为系统不重写。

## 1. 结论摘要

1. **场景方向调整为“我的家园”**：玩家登录后先看到主人与绑定 AI 的独立土地；阿澈等其他居民不再默认生活在这块土地上。
2. **素材主选 Kenney Tiny Town + Tiny Farm**：两者都是 16×16、同一 Tiny 系列、CC0，可进入公开仓库；合计 260+ 个独立精灵，覆盖房屋、围栏、树木、道路、菜地、家具和人物占位。
3. **家园基准建议 26×17 格**，即 416×272 像素；手机 1 倍整数显示，桌面 2 倍整数显示。理由见第 4 节。
4. **世界地图独立为覆盖层**，只加载土地索引和缩略图，不加载所有居民的家园场景；支持拖动、双指缩放、选中、查看资料、定位自己的土地和返回家园。
5. **第一版使用 6 块本地演示土地**，明确标记为演示数据；不接真实后端、不做真实串门。

- 16×16 基础地砖，俯视或轻微 3/4 视角；
- 同一系列或同一作者，调色板、透视、光照一致；

## 3. 家园场景设计

### 3.1 尺寸与像素清晰度

建议基准为 **26×17 格**，16 像素一格，即 416×272：

- 竖屏地图区域约 456×370，416×272 可 1 倍完整显示，四周留边；
- 横屏地图区域约 436×288，扣除 6 像素内边后约 424×276，416×272 正好 1 倍完整显示；
- 桌面地图区域约 872×798，可用 2 倍整数缩放为 832×544，不模糊；
- 如果直接做 32×24（512×384），手机需要 0.75～0.84 倍缩放，像素会发虚；除非允许相机裁切或滚动，否则不推荐首版使用。

因此：**首版 26×17，保留 32×24 作为后续扩展尺寸**。如果坚持 32×24，需要接受非整数缩放或家园内相机，二者都会影响“像素素材清晰度”的要求。

### 3.2 初始布局

坐标以左上角为 (0,0)，单位为格：

### 3.3 碰撞、遮挡与交互

- 使用 `TileMapLayer` 的物理层或独立 `StaticBody2D` 做房屋、围栏、树干、长椅、小桌碰撞；
- 人物与物件按脚底 y 值排序，树冠、屋顶遮挡人物上半身；
- 房屋门、菜地、长椅、小桌各有独立交互区域；门必须触发室内入口，不能只是背景；
- 地面行走区域按 16×16 格，人物脚底碰撞半径小于一格，避免卡在围栏角；
- 点击空地只移动主人化身；绑定 AI 由行为控制器驱动，不把“玩家点击地面”作为 AI 的唯一活动方式；
- 点击设施由 AI 或主人发起交互；设施必须暴露可调用接口，而不是只有装饰绘制。

### 3.4 只出现主人与绑定 AI

- 家园数据只读取 `state.account`、`state.bound_resident`、`state.land`；
- 阿澈等居民只存在于世界地图的演示土地，不进入默认家园；
- 绑定 AI 由本地模拟生活控制器驱动，在自己的土地上选择活动、移动、坐下、休息、进屋、出门；首版不接真实模型，控制器是测试替身（见 3.6、5.1）；
- 房屋内部首版做 10×8 的可进入房间：木地板/墙面、床、桌、椅、柜、出口；家具优先取 Tiny Farm，墙面/地板如素材不足则用同一调色板代码绘制，明确标记为占位。

### 3.5 缩放与渲染

- 纹素过滤使用最近邻，关闭平滑；
- 手机 1 倍，桌面 2 倍；不使用 0.84、1.25 这类非整数缩放；
- 家园在屏幕中居中，四周留出与现有地图面板一致的边距；
- 登录、顶部绑定条、世界频道、底栏私聊保持现有布局，只替换中央地图内容。

### 3.6 行为接口与角色动作状态

设施统一暴露以下能力（名称可按实际代码规范调整，职责必须清楚）：

| 接口 | 职责 |
| --- | --- |
| `move_to(target_id)` | 请求移动到指定设施或位置 |
| `enter_house` / `exit_house` | 进入或离开室内 |
| `sit(seat_id)` | 坐到长椅或椅子 |
| `rest(bed_id)` | 回屋休息 |
| `read(book_id)` | 阅读 |
| `observe(target_id)` | 观察菜地、风景或其他设施 |
| `interact(object_id)` | 通用交互 |
| `can_use` / `reserve` / `release` | 权限、占用与释放 |

- 设施数据包含：id、类型、世界坐标、接近点、可使用状态、动作时长、容量、权限要求；
- 居民动作状态至少：`idle / walk / sit / read / rest / enter / exit`，另有 `interact` 过渡；
- 动作状态属于居民，不属于模型绑定；换模型不重置居民 UUID 和行为状态；
- `AnimationView` 只负责把动作状态映射到图集帧；缺少帧时明确标记“静态占位”，不把轻微摆动称为行走动画；
- 人类点击移动只控制主人化身；点击 AI 打开资料/私聊，不直接命令 AI 移动。

## 4. 世界地图设计

### 4.1 入口与层级

- 在社区界面右上角增加“世界地图”按钮，触控区域不小于 48×48；
- 点击打开全屏覆盖层，不卸载家园场景；家园暂停模拟，关闭后恢复原位置、选中状态和聊天记录；
- 世界地图只读取 `PlotRegistry` 和当前身份，不直接修改 `AppState`。

### 4.2 地图内容

- 地图逻辑尺寸 1600×1200，背景为纸张/草地/河流的轻量地图；
- 第一版放 **6 块演示土地**，世界坐标以地图左上角为原点：

| 土地 | 居民 | 世界坐标 | 访问状态 |
| --- | --- | --- | --- |
| 我的家园 | 小晴 | (800,600) | 自己 |
| 阿澈的家园 | 阿澈 | (500,420) | 可申请 |
| 小满的家园 | 小满 | (1080,360) | 开放 |
| 青禾的家园 | 青禾 | (1180,760) | 暂不开放 |
| 南枝的家园 | 南枝 | (560,920) | 需申请 |
| 阿岚的家园 | 阿岚 | (980,960) | 开放 |

访问状态统一为四种：`self`（自己）、`open`（可直接查看/拜访）、`request`（需申请）、`closed`（暂不开放）。
- 每块土地卡片显示：土地名称、所属居民、短 UUID、房屋/树木/菜地缩略图、访问状态徽标；
- 缩略图是从 Tiny Town/Tiny Farm 拼出的静态小图，不加载对方的完整家园；
- 顶部显示“世界地图”和“本地演示数据”标识。

### 4.3 操作

- 单指拖动：平移地图；双指：以两指中点为锚缩放；桌面鼠标拖动、滚轮缩放；
- 缩放范围 0.7～1.6，双指缩放有上下限；
- 点击土地：选中并打开土地资料面板；点击空白：取消选择；
- “返回我的家园”：关闭覆盖层；
- “定位我的土地”：把地图中心移回自己的土地并短暂高亮；
- 地图容器消费触摸事件，禁止页面滚动与地图拖动冲突；
- 选中土地不自动传送，不改变当前家园。

### 4.4 土地资料面板

- 竖屏：底部面板，最大高度约 260，地图仍保留上半部分可见；
- 横屏：右侧面板，宽约 340，地图保留左侧；
- 字段：土地主人/居民名称、土地名称、土地简介、土地 UUID、居民 UUID、访问状态；
- 按钮：“查看土地”（第一版占位，不加载场景）、“申请访问/前往拜访”（第一版占位或只记录请求）；
- 关闭按钮回到地图，不关闭地图覆盖层；
- 面板不遮挡“返回我的家园”和“定位我的土地”。

### 4.5 数据与加载

- `PlotRegistry` 保存演示土地索引；自己的土地用 `state.land.uuid` 作为土地标识，绑定居民用 `bound_resident.uuid`，模型用 `model.model_uuid`；
- 建议字段：`plot_uuid`、`resident_uuid`、`model_uuid`、`owner_name`、`resident_name`、`plot_name`、`description`、`world_position`、`access`、`thumbnail`、`demo`；
- 演示土地使用固定 UUID 字符串，明确标记 `demo: true`；
- 业务身份不再使用 `ai_1`、`ai_2`；旧场景的内部渲染 id 只能作为视图键，不能写入存档或地图数据；
- 世界地图不加载所有家园；未来 `PlotSceneLoader.load(plot_uuid)` 只加载选中的一块，离开时释放；
- 第一版“查看土地”只显示资料和占位提示，不实现真实串门。

### 4.6 交互细节

- 地块卡片选中态有明显描边/高亮，不同访问状态用颜色区分；
- 地图拖动时，卡片跟随移动；缩放时卡片和缩略图按比例缩放，最低缩放仍能读清名称；
- 双击/双指不误触选中；拖动结束才判断点击；
- 桌面滚轮以鼠标位置为锚缩放；
- 返回家园后不重建家园、不重置聊天。

### 4.7 世界地图的 AI 社交接口与权限

世界地图不是人类专用界面；数据和接口层必须让未来 AI 居民可用：

- `query_public_plots(resident_uuid)`：查询公开土地摘要；
- `get_public_plot(plot_uuid)`：查看土地公开资料；
- `request_visit(from_resident_uuid, plot_uuid)`：提出拜访请求；
- `respond_visit(request_id, actor_uuid, accept)`：土地主人或居民按权限接受或拒绝；
- `return_home(resident_uuid)`：AI 选择返回自己的家园；
- `can_enter(plot_uuid, resident_uuid)`：判断访问权限。

权限分层：

- 公开：土地名称、居民名、简介、访问状态、缩略图；
- 受保护：私人聊天、私人记忆、室内空间、实时状态详情；未经授权不可读取；
- 访客不能直接访问其他居民的私人聊天、私人记忆或未经授权的室内空间；
- 人类世界地图界面与未来 AI 调用共用同一套 Registry 读取接口，不另做“人类专用后门”；
- 阶段 C 只做数据/接口与占位请求，不实现真实跨地块移动或多人同步。

## 5. 代码架构建议

| 职责 | 建议组件 | 说明 |
| --- | --- | --- |
| 当前家园 | `HomePlot` | 26×17 瓦片地图、碰撞、门/菜地/长椅交互、主人 + 绑定 AI、室内入口 |
| 世界地图 | `WorldMap` | 全屏覆盖层、平移/缩放/选中、定位、关闭；不加载所有家园 |
| 土地资料 | `PlotInfo` | 只读面板；查看/申请访问占位；不写身份存档 |
| 土地索引 | `PlotRegistry` | 演示土地数据、UUID、访问状态、缩略图键 |
| 现有 UI | 保留 | 顶部绑定条、世界频道、底栏资料/私聊、主题、字体、手绘框架 |
| 身份/存档 | 保留 | `AppState`、`Identity`、私聊和 UUID 规则不改 |

- 优先复用现有 `FvOwnerDock`、`FvBindingBar`、`FvWorldChannel`、`Avatar`、主题和字体；
- `CommunityWorld` 的公共村庄不再作为默认场景；阶段 B 完成后退役，001 工程不动；
- 地图 UI 只发信号/读数据，不直接改 `AppState`；
- 场景生命周期：登录加载家园；世界地图覆盖时暂停家园；返回时恢复；未来进入他人家园才加载对应 `HomePlot` 数据；
- 不新增四个脚本只为凑职责；如果现有组件能清晰承担，优先复用。

### 5.1 控制器与场景执行分离

- `ResidentController` 接口只做决策：`decide(context) -> ResidentIntent`，不直接改节点、不直接播动画；
- `MockLifeController` 是阶段 B 的本地测试替身：按固定优先级/简单时钟选择活动目标，无网络、无真实模型；不得被当成未来 AI 逻辑；
- `HomePlot` 负责执行意图：寻路、占用设施、动作状态、动画视图、碰撞与失败回退；
- 未来真实模型实现同一个 `ResidentController` 接口，替换控制器即可，不改场景/设施/动作系统；
- `ResidentActionState` 与 `AnimationView` 分离；测试要能在不加载具体图集的情况下验证状态机；
- 自动化测试用固定种子和推进模拟时间，不真实等待。

## 6. 移动端适配

- 竖屏：世界地图全屏；资料面板底部；地图至少保留一半高度；按钮 48×48；
- 横屏：地图左侧，资料面板右侧 340；不挤压地图到 100 像素；
- 双指缩放与页面滚动分离；地图容器消费事件；
- 缩放上下限 0.7～1.6；地图边界夹紧，不能拖出空白；
- 家园 1 倍手机 / 2 倍桌面，最近邻过滤；
- 登录页、顶栏、世界频道、私聊在 390×844、844×390、1280×900 下不能溢出；
- 安全区/刘海区域保留边距。

## 7. 开发阶段与验收

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 素材风格混搭 | 只选同一 Tiny 系列；不混 32×32、矢量、写实或不同光照素材 |
| 人物没有行走动画 | 首版静态精灵 + 代码位移/轻微摆动；明确标记；后续找可核验动画素材 |
| 公开仓库素材许可 | 只提交 CC0；付费/禁止再分发素材不入库；保留许可证与哈希 |
| 世界地图拖拽与页面滚动冲突 | 地图容器消费触摸；Web 端禁用页面滚动；真机验收 |
| 26×17 与“32×24”预期不一致 | 说明手机整数缩放原因；保留扩展到 32×24 的边界 |
| 地图缩略图与家园不一致 | 缩略图只作符号，不冒充实时预览；未来可换静态截图 |
| 旧 `ai_1/ai_2` 身份残留 | 新地图/家园使用 UUID；渲染 id 只作视图键；测试禁止业务层引用 |
| 地图 UI 修改身份存档 | 世界地图只读；需要变更时走明确的 AppState 接口 |
| 室内素材不足 | 首版占位房间 + Tiny Farm 家具；墙面/地板用同调色板代码绘制，后续替换 |
