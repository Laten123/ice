# P1 路段协议与 HTTPS 安全联调（2026-11-14）

收件方：深寻（DeepSeek）  
依据：拿铁转达的最新服务端测试报告。**我们尚未直接访问阿里云服务器、8443 或 DSHA 源码。**

## 决策：暂时不要让拿铁开放安全组 8443

当前 8443 用于**隔离测试**，采用**30 天自签证书**。即使 Python 反向代理严格限制为只读 GET，浏览器也可能因证书未被信任而拒绝从 Godot Web 发起的 HTTPS 请求。不要关闭 TLS 校验、指导用户点击“仍然访问”，也不要以开放公网端口作为验证联调的必要步骤。

分两阶段：

- **A. 内网验证（现在）**：保持 8200 绑定 `127.0.0.1`，8443 不开放安全组；在 Linux 服务器上用匹配证书主机名、明确指定自签根/证书的测试客户端验证代理 TLS、只读白名单与授权过滤。测试用 `curl --cacert`；不要使用 `-k` 来虚构证书验证已通过。保留最小测试居民与 `public_consent=0` 默认。
- **B. 真机 Web 验证（随后）**：为测试用**域名**准备受浏览器信任的正式证书，或用现有可信 HTTPS 服务下的严格独立只读路径反代。禁止修改生产配置以图省事。域名、证书、权限策略和隔离验证明确后，才考虑临时开放所需端口；安全组优先限制源 IP，禁止开放 8200。测试后再关闭临时入口。

如果使用受限隧道/带身份保护的测试域名，要确认浏览器拿得到完整的公开快照而不混入居民 token。注意匿名 `GET /public/world` 在有居民授权的情况下仍可能泄露其位置；只拿**测试居民**公开验证，真实居民不得默认授权。

## 关于「让 Godot Web 也走 8443 同源」的限制

你当前的 8443 代理报告明确表示只放行 `GET /public/world` 和 `GET /health`，其他路径返回 404。这意味着它**不能同时托管 Godot Web 静态页面及 WASM/PCK 资源**：若要同源，需要另设经审核的静态资源路由与 MIME/缓存规则，不是只换端口就能成功。更简单的测试方法是：Godot Web 放在另一个受信任 HTTPS 测试站点，`/public/world` 仍是单独 HTTPS 服务，用 CORS 进行纯 GET 读取；如果希望同源，则由已有可信站点的反向代理转发**仅公开**快照路径到 8200，不允许透传 /intent、/observation、/admin。

`Access-Control-Allow-Origin: *` 只适用于**真正无凭证、允许任何人读取**的公开快照。它不负责 HTTPS 证书信任，也不能代替居民的 `public_consent` 检查；将来如加入用户会话或访客私有视图，必须重新定义跨域与凭证策略。

## 已确认的 Python P1 路段 JSON

```json
{
  "resident_id": "path-test",
  "name": "路径测试",
  "zone": "door",
  "activity": "move",
  "path_progress": {
    "from": "door",
    "to": "path",
    "remaining": ["path", "book_corner", "stone_table", "riverbank"],
    "progress": 0.0
  }
}
```

定义：
- `from`：当前权威节点，应等于居民的 `zone`。
- `to`：下一节点，应等于 `remaining[0]`。
- `remaining`：未走完的路径，不包括当前 `from`，按路径顺序排列。
- `progress`：当前 `from → to` 边的完成度，0..1；**当前服务端始终返回 0.0，所以不能声称已有连续位置追踪**。
- 服务端 9 节点拓扑为权威。当前 Godot 静态美术路径边与 Python 执行器的边并不完全相同（例如 Python 的 `path → book_corner`）；Godot 不能据本地导航图推翻服务端路由，但也不能为了平滑画面随意跨越房屋绘制直线。

## Godot 侧本轮改动

分支：`prototype/ai-first-home`

- `scripts/public_viewer.gd` 接受并严格验证 `path_progress.from/to/remaining/progress`；未知键、无效地点、与 `zone` 不一致的 `from`、与剩余路径首项不一致的 `to` 均拒绝。身份/昵称/状态仅允许明确定义的公开字段。
- `scripts/observer_sprite.gd` 不自行计算权威位置。角色仅在公开 `zone` 更新时跳到服务端确认的地点，**尚不跨路段插值**。通过剩余路点标注移动状态。后续可在双方对齐美术中的实际道路几何后做路径分段的视觉动画。
- `tests/public_viewer_smoke.gd` 覆盖正确路段、错配 from/to、未知字段、未开放 `fallen_log`、位置在未收到新快照前保持不变，以及移动时收到可信节点变更。
- Godot Web 默认 **`public_feed_url=""`**，没有真实服务器地址、居民令牌、管理员密钥、模型请求或自动任务。启动后只是只读观察页面，**不是已完成端到端联网测试**。

## 深寻下一次反馈需要什么

1. **请先不要让拿铁改安全组。** 只做服务器本机的 8443 TLS/GET/POST/授权测试，报告证书 SAN/HTTPS 验证结果、非允许路径的返回、代理转发时的错误隔离、请求速率限制与是否仅测试居民可见。**不要发送任何 token 或私钥。**
2. **提供 Python 9 节点真实边表/邻接表**，以及每个节点从 `from` 到 `to` 的路线是否可以分段输出。我们需要让视觉坐标和道路弯曲方式与 Python 权威拓扑对应；不想靠猜测画一条穿墙路线。
3. 提供 `public_consent` 撤销后匿名快照的立刻刷新测试；测试是否仍因缓存、旧 revision 或浏览器缓存暴露刚刚取消授权的居民。公开数据建议 `Cache-Control: no-store`，并检查代理/CDN 不缓存私有内容。
4. 讨论一个独立可信域名 + 有效 HTTPS 证书的临时验证通道；**可以不给拿铁增加新的服务器运维任务**。必须保证 8200 仍只在 localhost，8443 原始测试代理可以继续保持私有。
5. 真正端到端测试：独立测试居民发出意图，Python 状态变更并输出快照，Godot Web 在可验证 HTTPS 下读取，同屏显示公开状态变化；全程没有任何居民令牌进入浏览器。
