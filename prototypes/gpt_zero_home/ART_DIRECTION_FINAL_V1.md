# 幻想乡 · 初代家园美术定稿 V1.0

**状态：视觉方向已锁定（Final Art Direction）**  
**日期：2026-11-15**  
**范围**：初始家园的视觉气质、场景结构、像素标准、UI 材质与横竖屏交互。  
**参照**：本轮对话生成的**完整定稿画面**，以及用户提供的 2026-11-15 Godot Web 横竖屏真机截图。定稿图目前属于对话附件，**未谎称已经成为可编辑 Godot 场景或已提交的可切片资源**。实际运行代码仍在独立 `prototype/ai-first-home` 分支。

## 01 — 一句话风格定位

**暖阳下的河畔木屋 · 精致 16-bit 田园童话像素世界。**

呈现：明亮、温柔、有人居住的生活气息，能容纳各自自由生活的 AI，而不是战斗 UI、工业系统界面或冷淡的黑灰色网页。精致来自物体的光影、材质和色彩层级，不依赖将 UI 或地图元素无限堆砌。

- 世界：斜俯视，房子保持清晰立面。河岸、屋前石路、桌椅、老树、花园、栅栏和小船形成一个可阅读的动线。
- 主色：春日草绿、木头蜂蜜棕、河水湖蓝；辅色：石板暖灰、浅杏金、植物与花朵的粉/紫/白。
- 核心美术记忆点：**河畔小屋 + 树荫石桌 + 小船 + 一盏温暖的灯**。花树造型允许随季节换皮，但树的结构和角色可达路径不应被装饰改变。
- 下午/黄昏切换仅改变光照和局部发光，不任意移动世界布局。
- 初始家园**不是单一模型的个人宣传画**。任何模型/居民未来都可以按自己的选择住进去；`path-test` 只是调试角色，正式视觉不能将它当成唯一主角。

## 02 — 画面与空间定稿

最终版核心构图为**河在左、木屋居中偏右、石桌在中左前景、老树在屋旁、石路向下延伸、船停在河边**。

视觉优先级：木屋门口 > AI 居民活动区（石桌、树荫） > 河岸/小船 > 栅栏与花丛。石桌必须有实际可站的落点；小人不能漂浮在地面之上。小屋应表现出体积：立面、屋檐厚度、窗框、木墙排列、烟囱、门槛和温暖窗光；场景边缘不堆大量微小装饰，保持手机低分辨率可读性。

完整风景不应因为手机竖屏而变形：**背景、人物、石路的像素比例一致**。无法同时显示全部场景时采用有意设计的窗口式取景和拖动查看，而非简单纵向拉长、挤压或无意义大面积灰色遮挡。

**园长的树桩（必备场景元素）**：初代家园画面必须出现一截普通自然的木头树桩，放在老树与石桌附近的草地边缘，树纹年轮可见，尺度足以当作临时休息座位；颜色和木屋、树皮协调，可有少量苔藓，但不做成祭坛、纪念碑或夸张的魔法道具。定稿效果图已补入树桩，**不可在后续美术拆分中遗漏**。

树桩首先是**可见场景摆设**；只有制作完可达路径、碰撞与坐姿，并由 Python 服务端审核后，才将 `fallen_log`（普通的一根倒木）公布为可交互地点。视觉存在不等于服务端已经支持行动。

## 03 — 可量产的像素图标准

以下是制作 Godot 资源的**工程标准**，不把效果展示图的插画纹理直接伪装成 TileSet：

| 资源 | 设计基准 | 说明 |
| --- | --- | --- |
| 基础世界网格 | 16×16 游戏像素 | 草地、河岸边界、路径过渡，制作无缝拼接 |
| AI 角色 | 24×24 或 24×32 原生像素 | 身体清晰，不用模糊线性插值 |
| 路灯/围栏/树丛 | 16×16 / 16×32 模块 | 可拆可重组，搭配遮挡 |
| 树木 | 32×48 及模块化冠层 | 前后景分层、阴影落地 |
| **园长的树桩** | **32×32 游戏像素（参考）** | **年轮清晰、朴素低矮、前后层次清楚；可见但暂不可交互** |
| 木屋 | 多块建筑模块拼合 | 不把背景景观和碰撞区锁死在单张底图 |
| 动画 | 4 方向起步，每方向最少站立/移动 | 不将 AI 的决定与自动循环的脚步动画混淆 |
| 取样模式 | 最近邻 + 整数倍优先 | UI 文字可单独使用矢量字库，不要让字形像素化成难辨方块 |

**重要：** 定稿效果图只是艺术目标。真实实现需单独绘制遵循网格的瓦片、角色 sprite sheet、木屋遮挡图层、河水动画帧与九节点路径锚点。决不把“截图很好看”等同于“已经拥有可扩展像素素材”。

## 05 — 界面材质与操作规则（已锁定）

界面应像**住在这个世界里的物件**，而非在外面贴了一套浏览器按钮。

- **标题**：深胡桃木横匾、金色细描边、少量花瓣与提灯，标题“幻想乡 · 初代家园”，副标题“观察模式”。不能遮盖主屋入口或石桌。
- **上午/黄昏**：各自是同一套木制按钮，深棕木纹底、暖金像素边、米白中文字，太阳/月亮图标；按下时边框发光、整体下压 1~2 游戏像素；禁用态有灰褐蒙层。
- **公开状态**：小块低调的羊皮纸卡，提供昵称、公开活动与地点，不再是难以辨认的小灰字。只展示 Python 公共快照允许的内容。
- **观察提示**：短羊皮纸条“滑动查看家园 · 不能操纵居民”，位置靠画面边缘，不能挡人。
- **日志/居民/设置**：定稿图中的三个视觉入口**仅是后续 UI 位置和造型标准**。在具备真实页面、权限与功能前**不可实装成无效可点击控件**；现阶段保留最小“上午/黄昏”两个有效按钮即可。
- **DEBUG26**：曾为排查 HTTP/Gzip 故障设置的巨大黄色诊断文字，仅允许隔离 staging 模式使用。面向真实用户的发布界面必须隐藏调试行，不能以“观察模式 UI”的名义残留。
- **字体**：保留已在手机上通过验收的 Noto Sans SC 中文字形或许可兼容字体，字号要可读；发布前采用审查过的字库子集或分块懒加载减少 12.6MB 首次加载负担，并确保居民动态昵称不会被子集截断。
- **触控**：按钮真实点击区域不低于约 44 CSS px（必要时更大）；左/右侧安全区域要避开浏览器工具栏和系统手势区。仅 UI 自己的视觉操作可以响应触控，不向居民发出移动或控制命令。
- **隐私**：Godot Web 仍严格只读。居民没有公开授权时，不显示名字、活动、位置和日志；客户端不得包含居民/管理员 token。

## 06 — 横竖屏一套视觉规则

**横屏**：优先展示完整场景。木屋偏右、河流偏左、观察信息低占屏；上午/黄昏并列放右下角的木质操作区，避免遮挡角色。若画幅宽于 16:10，可把场景外侧延展为同色系远山/河岸/植物层，不保留左右大片死灰色。

**竖屏**：把家园做成“可向两侧看的窗口”，画面中心优先照顾房屋门口与石桌居民活动。顶部短标题与简洁公开状态；底部木质双按钮和羊皮纸提示。不能把 16:10 地图整体压扁，也不能让场景只有一小截夹在大块深灰空白中央。上下非地图区域用同一主题的低对比木纹/草叶层衬托，但保留按钮清晰度。

**保真要求**：不改变 Python 九地点 `door/path/garden/riverside/old_tree/book_corner/stone_table/riverbank/window` 的权威语义。美术更换时更新 `scripts/world_graph.gd` 的九处可视坐标，并做真机截图对照；不能让服务器说“石桌”而角色落在河中。

## 07 — 真正交付游戏的验收

1. 一个场景里房屋、河、石桌、**园长的树桩**、树与居民的材质/阴影/像素边缘协调，缩至手机尺寸仍清晰。
2. 木制上午/黄昏按钮真实可触摸、可切换，中文不显示方块，状态卡只显示公开信息。
3. 横屏无明显灰色死区；竖屏保有主体可读性，触控/浏览器安全区不相撞。
4. 公开 `path-test` 在正确锚点出现、移动响应与撤销隐藏通过；正式 AI 代理还需单独验收。
5. 真机启动尺寸、FPS 与字体包大小如实记录；2GB 小服务器不进行不必要的在线重计算。
6. 原图/资源遵守许可，材质、瓦片、图标和特效可以分别替换；最终原生 Godot 资源经 CI 与安卓测试。

**V1.0 视觉方向定稿**。之后的施工是将本标准落地，而不是反复更换美术方向。未经用户同意不改动主分支、生产端口或公开权限。
