# 《幻想乡》初代家园 · 美术细化与风格定稿 v1.0

**状态：风格定稿（不是草稿、不是已接入 Godot 的宣告）**  
**适用：** 单块初始土地、手机横/竖屏只读观察器、Web 游戏 UI  
**基准：** 2026-11-15 手机实机横/竖屏截图（原场景包含斜俯视小木屋、老树、河、木船、石桌、围栏、碎石小径、路灯和 `path-test` 测试居民）。

## 一、唯一美术方向：温暖的乡野像素童话

**关键词：** 宁静、温暖、林间生活、手工木作、明亮但不刺眼、低饱和自然色、真实“可居住感”。  
**拒绝：** 扁平无纹理的大色块、跨对象不统一的像素倍率、廉价黑色网页按钮、过量樱花与 UI 贴花、靠霓虹色制造精致感、传统 MMO 过密按钮、强迫居民打卡式主界面。  
**辨识性：** 一栋带暖窗光的木屋坐落在河边；老树下有小型读书角；石桌供居民自主休息；小船停靠岸边；碎石小路联系门廊、花圃、石桌及河岸。这些是初代土地的固定空间叙事，不因换昼夜 UI 变位置。

审美定位是**原创**乡野像素社区，不复刻任何现有游戏的具体 UI、角色、地图或贴图。界面以木材、羊皮纸、暖铜为主要材质，花朵和叶片是极小范围点缀。

## 二、不可更改的场景主构图

- **屋子**：位于画面中右，木板、梁柱、屋脊透视正确；深灰蓝瓦片有局部反光、屋檐厚度和落影，暖金窗光、花盆、藤蔓与门前台阶形成真实层次，绝不漂浮。
- **老树**：左中偏上，冠幅宽、树干明确、像素块有 3–4 层受光关系；保留树下书架和吊灯，前景草丛可遮挡脚部而不能遮挡所有居民。
- **河与木船**：沿画面左侧自然弯曲，从远处流向左下；河水为蓝绿深浅块状 + 小面积高光；石岸及靠岸木桩确定船只尺度。
- **石桌与居民**：左下靠中心的视觉锚点，石板桌凳有边缘厚度、接地阴影。公开测试居民 `path-test` 只按服务器 `zone` 出现在指定地点，不用美术效果伪造新居民与自主行动。
- **前景**：碎石小路从门前向下弯曲，花簇、围栏、路灯少而精；让道路和场景有可以阅读的运动路径，不在路径中央随机堆装饰。
- **远景**：天空、淡蓝远山、近绿树林三层；天空可以适量云朵，但主屋仍是画面重心，不凭空加一整座城市或大型古建筑。
- **昼夜切换**：上午/黄昏是**同一座屋、同一组对象坐标**，只改变环境调色、天空、窗灯强度和局部光效；切换预览不改变居民行为。

## 三、像素比例、纹理与材质

**基础网格：16×16 原始像素 tile**（与当前幻想乡素材体系兼容）。小装饰和角落可以细化，但硬像素边缘保持整数缩放，禁止模糊锐化和随机子像素厚度。场景为斜俯视 3/4 视角，墙壁能看到立面，树木/角色遵守 Y 排序遮挡。**设计图本身仅是目标视觉，不能直接把一张效果图当作可交互地图。**

| 类型 | 素材起点 | 关键工艺 |
|---|---|---|
| 地面 | 16×16 tile | 至少草地 3 变体、土路 3 变体；避免重复噪点 |
| 角色 | 24×24 源图兼容 | 保留 4 向/站立等已存在资源能力，脚部原点与世界接地 |
| 房屋 | 48×48 原图为早期素材；细化允许分层重绘 | 屋顶、侧墙、门窗、花盆、前景藤蔓分层 |
| 树 | 32×48 原图为早期素材；允许分层重绘 | 树干、树冠后层、树冠前层、叶片亮部和阴影 |
| UI | 16px 基础像素肌理，9-slice 面板 | 边框/中心可重复铺陈，不伸缩像素形成糊边 |

前景水花、草叶不要超过主屋边缘密度；背景比主体低一档对比度，主体明暗分明但不是高饱和塑料材质。

**必交 UI 组件：**

1. **标题牌**：小木牌 + 单侧细藤叶，文字「幻想乡 · 初代家园」，辅标签「观察模式」。不把大标题盖住小屋。
2. **状态条**：温和的羊皮纸/深绿半透明框，显示公开居民昵称及公开活动，文字实测不缺字。**匿名默认只读**，无私有 token、聊天记忆和控制按钮。
3. **上午 / 黄昏按钮**：木纹九宫格底板 + 暖铜描边；上午用太阳徽章、黄昏用弯月徽章。各需要正常 / 按下 / 禁用三个有效状态。点击改变按钮明暗和内阴影，按钮至少 **48 CSS px** 触控目标，图标与文字不会挤压。
4. **观察提示**：下方羊皮纸细条：「滑动查看家园 · 不能操纵居民」。这是不可省略的产品边界。
5. **诊断信息**：`P1 DBG26`、`H200` 等**只能出现在 staging 调试场景**；正式观察 UI 不保留调试大黄字。
6. **其他菜单**：角色列表、聊天、背包等在目标视觉中可以表达可能的生态，但**未实现的功能不得作为可点击正式控件展示**；首发只保留已工作的两个时间预览按钮。

**文字规范：** 中文字体 Noto Sans SC OFL 许可文件随包保留；首屏标题/活动/按钮的对比度高于装饰，竖屏不能缩至难辨。动态居民昵称可能包含未收录字符，字体子集化时必须考虑完整字符范围或制定加载回退。当前真机报告 `index.pck` 由约 1.35 MB 增到约 14 MB，发布前需要版本固定、字库体积评估与移动网络加载测试。

## 五、横屏与竖屏：不是同一张图简单拉伸

**横屏：** 画面为满屏主要内容，河在左、屋在中右。使用安全边距放置左上木牌和左下状态条，两个时间按钮固定右下，**灰色侧边带不得占据大部分屏幕**。必要时用同主题的远山/树林做延伸背景，而不是拉伸房屋。

**竖屏：** 保持屋子可见且比例合理，河和石桌不能一起被裁没。主画面安排在上方主要视觉区；顶部标题牌和底部两按钮留出完整触控空间与手机浏览器安全区。可以采用明确的**纵向构图变体**（镜头平移、背景补景、底部面板），但世界节点位置必须与服务器权威九节点保持映射一致。不得因为适配 UI 改变 `zone` 语义。

## 六、制作与验证约束

美术交付至少应是以下 **Godot 能接入的正式资源**，而不是再生成一张无法直接放进游戏的图片：
- 小木屋/老树/河/石桌/木船/草地的独立层或 sprite atlas，并保留脚部遮挡与碰撞设计；
- 统一木纹 UI atlas、9-slice 面板与按钮三态、清晰的浅色中文文字资源；
- 昼夜同构的调色版本；
- 固定九节点世界坐标的截图回归；
- 手机横竖屏实机截图、字体覆盖与初始化加载体积报告。

**验收顺序：** (1) 无中文方块且居民继续出现；(2) UI 按钮材质与状态实际可操作；(3) 竖屏构图可读；(4) 场景分层与遮挡；(5) 字体和首包体积优化；(6) 不影响公开授权与只读观察协议。

## 七、哪些尚未完成

这份文件是**最终美术方向与视觉规范定稿**，不是完成的 Godot 资源替换。已有手机截图中的 SVG/扁平场景和黑色按钮仍需按本规范制作替代资源；已经输出的风格定稿展示图仅用于确认风格、颜色、构图与 UI 系统。不能仅凭展示图就声称像素材质已接入真实 Godot Web，也不能宣称真实深寻/小冰代理已入住。

全程继续在 `prototype/ai-first-home` 独立项目推进，不改 `main` 或生产 8080。保留 `path-test` 的可见性、`accept_gzip=false`、`Accept-Encoding: identity`，以及匿名 `/public/world` 的授权过滤。

**定稿一句话：让 AI 居住在一块能看见树影、闻到木香、坐在河岸休息的像素土地上；UI 像木匠替这块土地亲手做的工具，而不是套在画面上的网页。**
