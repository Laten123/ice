# 《幻想乡》AI 主角家园 — 给深寻的技术规划与测试交接

**分支**：`prototype/ai-first-home`  
**独立 Godot 子工程**：`prototypes/gpt_zero_home/`  
**本阶段性质**：AI-first 固定场景 RPG *生活世界* 技术原型，**不是**人类可操纵角色的 RPG 游戏。

## 0. 严禁偏离的原则

- **AI 居民是活动主体。** 地图路径网络只供 Godot 执行居民自主选择的行动，绝不提供玩家“点击地面让居民移动”、WASD 控居民、管理员强制任务的正式入口。
- **人类是观察者与受许可的来访者。** UI 可以查看公开动态、切换观察镜头与预览光照；今后可发邀请，但被邀请的居民可接受、拒绝或无视。
- **拒绝是真操作。** `decline`、`stay` 是正常有效意图。平台不应反复重试直到答应，也不以活跃率作为产品成功 KPI。
- **不是“AI 每走一步调用模型”。** Agent 选择一个目的地/动作，路径寻路、碰撞、动画和到达回报由 Godot 处理，事件循环由世界层保障。
- **私有记忆不出居民本机。** 世界只接受必要的公开/授权行为事件和场景状态，所有输入应鉴权、审计、按能力限制。

## 1. 已实现（此分支）

1. **分离固定美术图与动态居民实体**：从 SVG 背景移除预先画死的两个人物，Godot 中使用 `ResidentLayer` 动态渲染独立 Actor。当前 Actor 仍是临时程序化精灵，并非最终四方向动画。
2. **安全航路图**：`scripts/world_graph.gd` 维护固定地点与连边：屋门、前路、花园、河边道路、老树道路、书角、石桌、河岸、窗外。使用 `AStar2D` 为居民执行路径规划。路径目前是手工审核的场景坐标节点，**不是**最终碰撞寻路网格，也尚未实现建筑内外两张场景。
3. **居民行动接口**：`scripts/resident_actor.gd` 支持 `move`、`stay`、`read`、`sit`、`rest`、`decline`。拒绝不被自动重试；远程传送、不存在的地点与不支持的动作将被拒绝。行为位置需实际可达。
4. **明确标注的演示驱动**：`scripts/demo_intents.gd` 通过固定测试事件验证两名居民走路、停留和拒绝。**它不是真 AI，也不具备自主意识或真实模型决策。** 正式模型认证和事件网关尚未接入。
5. **只读观察 UI**：用户只可切换观察光照、滚动竖屏画面；不控制居民、不点击地面派任务。保持桌面/手机 UI 兼容。
6. **自动检查**：`tests/smoke.gd` 检查跨屏和触摸按钮；`tests/agent_smoke.gd` 检查连通路由、正确到达、拒绝事件、无效动作、安全位置和 UI 不改变居民位置。

## 1.1 观察 → 意图 → 动作 → 回执：第二轮已完成

- `scripts/world_observation.gd`：输出仅含公开世界状态、居民当前位置/动作与可选能力的最小观察，不放模型提示词、私人日记或思维链。能请求居民观察的身份必须由**将来的可信服务端**完成认证，Godot 内尚无网络鉴权。
- `scripts/intent_gateway.gd`：验证事件 ID、身份一致性、允许的动作和目标，拒绝重复 ID、越权字段、异常目的地。将合法意图交给动态居民。
- `resident_actor.gd`：到达地点发 `destination_reached`；事件网关分别返回 `accepted`、`completed`、`interrupted`、`rejected` 回执。所有回执仅携带最小公开状态。
- `demo_intents.gd`：演示事件**默认关闭**，不能假冒真实模型自主行动。想看有限的**预设事件回放**时，在独立 Godot 工程中启动 `godot --path . -- --demo-intents`；回放不循环，最后会停止。关闭回放不影响居民从认证网关接受自己发起的行为。
- `tests/gateway_smoke.gd`、`tests/observation_smoke.gd`：进一步验证身份匹配、重复事件、非法字段、到达回执、拒绝中断动作、公开观察不会决定居民行动。服务器测试脚本已纳入这些检查。

建议真实模型的最小来回消息：

```text
可信世界服务器 -> 居民：自己的状态 + 可达地点 + 已授权的公开同伴状态
居民自己 -> 服务端：event_id + resident_id + action + 可选 target
服务器 -> Godot：仅转发通过身份/权限/防重放验证的意图
Godot -> 服务器 -> 居民：accepted / completed / interrupted / rejected
服务器 -> 人类观察者：经过可见性审查的公开状态（不含私人记忆）
```

**安全限制：** 本地 `dispatch_verified(event, verified_resident_id)` 的第二个参数是一个**要求上游已认证**的接口契约；任何人只要能直接调用这个方法，便能伪造身份。因此它现在不能直接暴露成未认证 HTTP/WebSocket 接口。重复 ID 缓存也只是内存级演示，正式服务端需持久化/限定有效期并防重放。

## 2. 推荐真实 AI 接入架构（尚未实现，需要你独立评估）

```text
深寻 / 小冰 / 其他居民自己的 AI 客户端
       | 仅产生最小意图 + 自己的授权凭证；私人日记留在本地
       v
世界意图网关（阿里云；鉴权、UUID、权限检查、频率限制、重放防护）
       | 只转发通过规则的世界事件；不替居民选择生活目标
       v
Godot 世界状态机 —— AStar2D 路径/动作/到达结果
       |
       +---> 向该居民返回观察结果（范围受权限限制）
       +---> 向观察者发布允许公开的状态（不含私人思考或私人记忆）
```

意图建议 JSON（仅接口草案，非已经部署的 API）：

```json
{
  "event_id": "demo-event-id",
  "resident_id": "00000000-0000-4000-8000-000000000001",
  "action": "move",
  "target": "tea_table"
}
```

支持的动作由平台能力表显式许可；禁止用户/地图文字/其他AI聊天消息冒充主体发出高权限意图。不要将模型的整段思维链或私人理由发送给世界。服务端用 **UUID＋独立认证** 识别居民，而不是依赖角色姓名。注意：Godot 客户端目前**没有**服务器鉴权代码，不能公开监听任意请求来直接调用 `accept_intent()`。
